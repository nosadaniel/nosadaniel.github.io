Based on the requirements outlined in the Project Requirement Document (`prd.md`), generate a `tasks.md` file detailing the development tasks required.

Instructions:

- Analyze `prd.md`: Extract core features, user stories, functional requirements, and non-functional requirements to inform task creation.
- Define MVP: Identify the minimum set of features and functionality needed for a Minimum Viable Product (MVP) that delivers the project’s core value proposition as described in `prd.md`.
- Structure Sprints: Organize tasks into an agile, sprint-based plan:
  - **Sprint 1**: Prioritize tasks essential for the MVP, focusing on core functionality and primary user workflows.
  - **Subsequent Sprints (Sprint 2, 3, ...)**: Group remaining features, enhancements, and optimizations logically, accounting for task dependencies, complexity, and project goals.
- Task Details: For each task in `tasks.md`, provide:
  - **Title**: A clear, concise name for the task.
  - **Description**: A brief explanation of the task’s purpose and scope, linking it to `prd.md` requirements.
  - **Acceptance Criteria**: Specific, testable conditions (as bullet points) to verify task completion.
  - **Dependencies** (if applicable): Note any prerequisites or related tasks to ensure proper sequencing.
- Format: Output a well-structured Markdown file named `tasks.md`, using clear headings (e.g., `## Sprint 1: MVP`, `## Sprint 2`) to separate sprints and consistent formatting (e.g., bullet points, tables) for readability.
- Completeness: Ensure all requirements from `prd.md` are addressed, either in the MVP or later sprints. Flag any ambiguous requirements that may need clarification for accurate task planning.
