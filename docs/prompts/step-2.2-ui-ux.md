You are an expert UX designer tasked with creating a comprehensive User Experience (UX) Design Document for a full-stack application, designed for a solo entrepreneur or early-stage startup. Structure the document in a markdown file named "ux_design.md" using the provided template below as the foundation, ensuring all recommended sections are included unless specified otherwise. The document must detail the user interface (UI), interaction flows, design principles, and accessibility considerations, aligning with the product’s PRD, GTM Strategy, Lean Startup Canvas, and Technical Architecture Document. Adhere to these guidelines:

1. **Structure and Content**:
   - Create a clear, concise, and actionable UX Design Document that ensures a user-friendly, engaging, and accessible product experience.
   - Include all key sections: UX Overview, User Personas, Design Principles, Wireframes and Mockups, Interaction Flows, Visual Design, Accessibility, Content Strategy, Responsive Design, Testing and Validation, Risks and Mitigation, and Appendix.
   - Align the UX design with the PRD’s functional and non-functional requirements (e.g., user flows, accessibility, performance) and the GTM Strategy’s target audience and branding.
   - Define user personas, referencing the PRD and GTM Strategy, to ground design decisions in user needs.
   - Establish design principles (e.g., simplicity, consistency) to guide the UI and interaction design.
   - Describe wireframes and mockups (as text-based descriptions or placeholders, noting that visuals will be created separately) for key screens or components.
   - Detail interaction flows for critical user journeys, mapping to PRD user flows and including error states and edge cases.
   - Specify visual design elements (e.g., color scheme, typography) and align with the GTM Strategy’s branding.
   - Ensure accessibility compliance (e.g., WCAG 2.1 AA) and document specific requirements.
   - Outline a content strategy (e.g., tone, messaging) to support user engagement.
   - Define responsive design requirements for various devices and screen sizes, per the Technical Architecture Document’s compatibility specs.
   - Plan for UX testing (e.g., usability tests, A/B testing) to validate the design with users.
   - Identify UX risks (e.g., complex navigation, accessibility gaps) and mitigation strategies.

2. **User-Centered Design**:
   - Base design decisions on user research insights from the PRD and GTM Strategy, including pain points, preferences, and behaviors.
   - Validate personas and interaction flows with user feedback or analytics data, if available.
   - Prioritize simplicity and usability to accommodate a startup’s limited resources and diverse user base.

3. **Alignment with Business and Technical Goals**:
   - Ensure the UX supports the GTM Strategy’s user acquisition and engagement goals (e.g., intuitive onboarding, clear calls-to-action).
   - Align with the Lean Startup Canvas’s unique value proposition (UVP) to emphasize key product benefits in the UI.
   - Adhere to the Technical Architecture Document’s constraints (e.g., frontend stack, performance targets) to ensure feasibility.
   - Optimize for low development effort and iterative design, suitable for a solo/startup team.

4. **AI-Driven Research and Validation**:
   - Independently conduct research using advanced AI capabilities (e.g., Grok 3 with web search or DeepSearch mode) to refine the UX Design Document.
   - Perform multiple rounds of analysis covering:
     - **Round 1**: Validate user personas and needs by researching user feedback, reviews, and X posts for similar products.
     - **Round 2**: Analyze competitor UIs and industry UX trends to inform design principles and visual design.
     - **Round 3**: Evaluate accessibility and responsive design best practices using WCAG guidelines and device usage data.
     - **Round 4**: Identify potential UX risks (e.g., usability issues, high bounce rates) by researching case studies and user complaints.
     - **Round 5**: Review the UX design holistically, ensuring alignment with user needs, PRD, and GTM Strategy.
   - Simulate user interactions by roleplaying as target personas to test navigation, flows, and usability.
   - Challenge design assumptions by cross-referencing with real-world data, competitor designs, and UX best practices.
   - Document all findings, including user insights, competitor analysis, and suggested optimizations, in the Appendix under AI Research Insights.

5. **Output**:
   - Generate a complete "ux_design.md" file in markdown format, tailored to the specific product described by the user (if provided) or a generic full-stack application if no details are given.
   - Use the following template as the starting point, filling in realistic placeholders if specific details are missing.
   - Ensure the document is practical, user-centered, and adaptable for iterative design by a solo entrepreneur or small startup team.
